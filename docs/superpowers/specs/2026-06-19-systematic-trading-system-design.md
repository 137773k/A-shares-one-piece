# 系统化选股交易体系（优化版）— 设计文档

> 日期：2026-06-19
> 原则：**优化，不替代**。新增逻辑抽到独立模块，不动已验证可用的抓取/打分主路径。
> 视角：顶级游资。把三张方法论图（哲学层 / 周期判断层 / 硬筛选层）织进现有 `godhand-app`。

## 0. 背景与现状

现有系统（`server.js` ~3500 行 + `script.js` 前端）已具备：

- **周期模型**：5 阶段 `CYCLE_ORDER=[冰点, 混沌, 修复, 主升, 退潮]` + 不可逆环（`applyCycleIrreversibility`, `server.js:138`）
- **选股**：`scoreCandidate`（软打分 + 热度入围 + 筹码舒服度）、`classifyMarket`（周期判定）
- **炒作逻辑**：`buildSpeculation`（在途/透支/兑现）
- **K线画像**：`fetchKlineProfile`（MA 原始行、`avgAmount5`、放量、筹码）
- **买卖提示**：已有但为分散文字（`server.js:2393-2444`）

### 三张图与现状的差距

| 图片要求 | 现状 | 差距 |
|---|---|---|
| 6 阶段情绪周期（冰点/修复/主升/高潮/分歧/退潮） | 5 阶段（含"混沌"，无高潮/分歧） | 需扩展周期模型 |
| 硬筛选（均线多头/量比>1.5/成交额>5亿/主力净流入） | 软打分 | 缺硬门槛闸门 |
| 止盈止损区间 | 仅文字提示，无量化区间 | **最大缺口** |
| 交易模式×出手时机 | 有文字 buy/sell，分散 | 需结构化 |

### 关键设计决策（已与用户确认）

0. **【第一原则】选股做减法，不做加法**。候选池就是热度前50（东财前50 ∪ 同花顺热榜），在这个池子里**极致筛选可能性**。宁可留少不留多——留 3-5 只高确定性远好于留 20 只模糊标的。硬闸门越严越好，"误杀刚突破的票"是特性不是 bug（呼应哲学"宁可错过绝不接最后一棒"）。退潮/冰点周期下最终池小甚至接近空仓，是正确结果，不是故障。
1. **周期模型**：5 阶段主框架 + 子标签（不扩展为独立 6 阶段，降低风险，符合"优化不替代"）。
2. **筛选方式**：硬闸门 + 软打分双层。
3. **止盈止损**：交易模式 × 情绪周期 双维度结合。
4. **主力净流入降级策略**：限流/缺数据时降级为"待确认"并扣软分，**不直接剔除**（防止因数据问题整池清空——注意：这是防数据故障，不是放宽筛选标准）。

## 1. 总体架构

整个体系是一条**做减法的漏斗**——每一层只减不增，目标是把热度前50收敛到 3-5 只高确定性标的：

```
热度前50候选池(东财前50 ∪ 同花顺热榜)
   → 哲学纪律(护栏) → 周期闸门(能不能出手) → 硬筛选(严格剔除,留谁)
   → 软打分(排序,复用现有) → 交易计划(怎么打) → 止盈止损(何时走) → 前端展示
```

漏斗的每一层都是减法：周期闸门可能整池否决（退潮/冰点→空仓），硬筛选剔除不满足趋势结构/资金活跃的票，软打分再排序取头部。**最终展示的是收敛后的少数高确定性标的，不是全池。**

新增逻辑全部集中到一个独立模块 **`trading-rules.js`**（纯函数为主），由 `server.js` 在管线里调用。理由：
- 纯函数可单独单元测试（superpowers 查 bug 的着力点）。
- 不污染 `server.js` 已验证可用的主路径。
- 隔离边界清晰：每个函数"输入股票/市场数据 → 输出判定"，可独立理解与测试。

### `trading-rules.js` 对外接口（草案）

```
classifySubPhase(marketState, limitStats, snapshot) -> { subPhase: string, reasons: string[] }
hardGate(stock) -> { pass: boolean, hardFails: string[], softFlags: string[], metrics: {...} }
tradePlan(stock, marketState) -> { mode: string, entryTrigger: string, entryZone: string, avoid: string }
stopProfitLoss(stock, mode, marketState) -> { stopLoss: {pct,basis}, takeProfit: {pct,basis}, position: string, riskReward: number }
```

`server.js` 改动最小化：在 enrich/score 管线里依次调用，把结果挂到 stock 对象上，前端读取渲染。

## 2. 第1层 · 哲学纪律（图1）— 编码为护栏

图1 的 5 条变成系统硬约束，贯穿其他层（本层不单独成模块）：

| 哲学 | 系统落地 |
|---|---|
| 只做主线不做杂毛 | 硬闸门 + 现有主线识别；非主线票即使热度高也降级 |
| 只做资金合力不做幻想 | 主力净流入 + 双榜共振 作为闸门/重权 |
| 宁可错过绝不接最后一棒 | 周期进入"高潮/分歧"子标签 → 自动收紧止盈、降仓、禁新仓 |
| 收益=胜率×盈亏比×仓位 | 每只票显示盈亏比估算(止盈空间÷止损空间) + 建议仓位(按周期) |
| 不预测而是应对 | 全规则化 + 周期不可逆(已有) |

## 3. 第2层 · 周期判断（图2）— 5阶段 + 子标签

保留 `CYCLE_ORDER` 和不可逆环不动。`classifyMarket` 返回值新增 `subPhase` 字段（由 `classifySubPhase` 计算），把图2 的 6 阶段映射到 5 阶段 + 子标签：

```
图2的6阶段  →  现有5阶段 + 子标签
冰点期      →  冰点
修复期      →  修复
主升期      →  主升 · subPhase="主升初/主升中"
高潮期      →  主升 · subPhase="高潮加速"   (一致性极强+加速板增多 → 炸板率低、高度板涌现)
分歧期      →  主升 · subPhase="高位分歧"   (高位震荡+炸板增加 → 炸板率上行、连板断板)
退潮期      →  退潮
混沌        →  保留为底部试错桶
```

**判定数据**：用现有的涨跌停/炸板/连板高度 + 指数，不需新数据源。

**子标签驱动动态策略**（图2）：
- 冰点/退潮 → 降仓位 + 提风控权重 + 减少追高 + 优先空仓
- 高潮加速 → 兑现优先、不接最后一棒
- 高位分歧 → 减仓、只做转强

## 4. 第3层 · 硬筛选（图3）— 硬闸门 + 软打分双层

`hardGate(stock)` 在入池前跑，分两组按数据可靠性分级：

### A. 趋势结构（全部可从现有 K 线算 → 真·硬闸门，不满足直接剔除）

- 收盘价 > MA5
- MA5 > MA10 > MA20
- MA5 持续向上（近 2-3 日斜率 > 0）
- 最近 3 日无放量长阴破位（无"大阴线 + 放量 + 跌破 MA10"的日子）

> 实现说明：`fetchKlineProfile` 现已取 120 日 K 线原始行，但**未计算 MA5/10/20**。需在该函数补算 MA 序列并暴露给 `hardGate`。

### B. 资金活跃度（数据有风险 → 强软门，分级处理）

- **5 日均成交额 > 5 亿**：`fetchKlineProfile` 内已算 `avgAmount5`（单位：元），但**未暴露在返回值**，需暴露为 `avgAmount5Yi`（亿）后硬卡
- **量比 > 1.5**：**已有** `stock.volumeRatio`（clist 字段 f10，`server.js:926`），直接硬卡，无需新增抓取
- **当日主力净流入 > 0**：**已有** `stock.mainInflowYi`（clist 字段 f62，`server.js:929`），直接硬卡。注意：现仅当日值，图3要求"最近3日"——多日历史为未来增强（YAGNI，本期用当日）。`mainInflowYi` 缺失/为 0 → 降级为"待确认"扣软分，**不直接剔除**（防数据故障整池清空）
- **分时承接明显**：无可靠源 → 仅作提示，不入闸门

### 输出与后续

- 通过闸门 → 进入现有 `scoreCandidate` 软打分排序（完全复用）
- 未通过 → 进剔除区，显示失败项（如"MA5 走平""无主力净流入"）
- **做减法收敛**：软打分排序后取头部高确定性标的（目标 3-5 只，最多不超过约 8 只），其余即使通过闸门也归入"次选/观察"而非主推。强周期（主升）可适当多留，弱周期（退潮/冰点）从严甚至空仓。最终主推数随周期动态，不强凑数量。

## 5. 第4层 · 交易模式 × 出手时机

把散落的文字 buy/sell（`server.js:2393-2444`）收敛成 `tradePlan(stock, marketState)`，输出三种游资模式之一 + 结构化出手时机：

| 模式 | 出手时机(entry) | 适用 |
|---|---|---|
| 打板/接力 | 首次分歧转强、炸板回封、换手确认后回封；强一致秒板不追 | 主升核心龙头 |
| 低吸/承接 | 回踩 MA5/分时均价不破、缩量企稳再放量转强 | 中军、趋势回踩 |
| 趋势/二波 | 二波突破放量、回踩不破趋势线 | 容量趋势票 |

模式选择沿用现有 setup/ticketType 判定逻辑，结构化封装，不重写判定。

## 6. 第5层 · 止盈止损 — 交易模式 × 周期 双维度

`stopProfitLoss(stock, mode, marketState)` 输出区间。基线按模式，周期做修正。

### 模式基线（游资实战默认值）

| 模式 | 止损基线 | 止盈基线 |
|---|---|---|
| 打板/接力 | 跌破分时均价线 或 次日不及预期 **-3%~-5%** | 次日冲高溢价 **+5%~+10%** 兑现 / 分歧不接最后一棒 |
| 低吸/承接 | 跌破买入参考(MA5/分时均价) **-2%~-4%** | 反包回封 / **+8%~+15%** |
| 趋势/二波 | 跌破 MA5(趋势止损 MA10) **-5%~-8%** | 高潮加速分歧 / MA5 走平 / **+15%~+25%** 分批 |

### 周期修正系数

- 主升进攻 → 止盈放宽一档
- 高潮加速 → 止盈收紧锁利
- 高位分歧 → 止损上移到成本/分时均价、减仓
- 修复/混沌 → 区间收窄、小仓试错
- 退潮/冰点 → 最紧止损（破位即走）、优先空仓

### 附加输出

- **建议仓位**：退潮/冰点 轻仓或空仓 → 主升核心可重仓
- **盈亏比**：止盈空间 ÷ 止损空间（呼应哲学#4）

## 10. 范围边界（YAGNI）

- 不动 `expo-app/`（无关的健身 App）。
- 不重写抓取主路径、不改周期不可逆环、不替换 `scoreCandidate`。
- 不实现真实下单/交易执行——本系统是"选股 + 交易决策提示"，非自动交易。
- 分时承接只做提示，不做硬指标。
