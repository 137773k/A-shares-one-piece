# 量化因子统一说明

- 文档修订：2026-08-23
- 因子投影版本：v6
- 严格决策链版本：v3
- 正式决策输出：`payload.unifiedDecisionChain`
- 统一因子投影：`payload.unifiedQuantFactors`
- 实现入口：`quant-decision/index.js`

## 1. 目标与边界

本统一层解决“同一批市场数据在不同页面出现不同口径、重复计分、权限冲突以及多个模块分别选股”的问题。现有模型继续负责生产证据，`unifiedDecisionChain` 是唯一有权输出正式结果股票和仓位配比的执行器。

明确保留以下独立性：

- 大周期与小周期是两套不同算法。大周期负责宏观结构，小周期负责大周期内部的短期节奏；两者并列输出，任何一方都不能覆盖另一方。
- 旧炒作偏好与新炒作偏好叠加使用。旧模型负责板块轮动、聚焦或个股轮动等宏观组织，新模型负责低位启动、高位趋势、连板情绪等微观资金路径。
- 全市场赚钱效应、短线核心赚钱效应、可交易赚钱效应是三个统计范围，不得共用一个“赚钱效应”标签互相替代。
- 市值载体目前只作观察因子；未完成样本外验证前，不参与个股评分和交易权限。

## 2. 唯一决策链

统一链路必须严格按以下顺序执行：

1. 市场阶段：大周期、过渡节点与小周期分别计算、共同进入阶段节点；大周期只允许五态。
2. 交易许可 / 交易价值 / 交易仓位权限：所有权威权限取交集，先确定是否值得交易和组合仓位上限。
3. 赚钱效应：只有短线核心赚钱效应中的具名载体可以继续，不得用全市场上涨代替短线载体，也不得拿下游最终股票反向定义本层。
4. 题材：赚钱效应载体必须属于已确认题材。
5. 股票模式：题材内股票还必须符合当前周期已确认的资金路径与载体类型。
6. 个股硬门槛：个股交易资格、核心地位、次日入场资格、价格完整性和风险门槛全部通过。
7. 输出结果股票：最多 5 只，允许 0 只，不足不得补票。
8. 输出结果股票的参与价值与仓位配比：只在前七层通过后计算，不能反向打开权限。

执行器采用逐层短路。上一层失败时，后续层标记为 `not_evaluated`，正式股票结果为空、仓位为 0%。`bestPicks`、明日决策和页面候选读取同一链路过滤后的结果；旧字段只作证据或迁移兼容。

### 2.1 前置交易价值与后置参与价值

- `authorization.tradeValue` 是市场层交易价值，只由市场阶段和权限交集决定，当前只输出规则等级，不生成未经校准的数字分数。
- `result.stocks[].participationValue` 是个股层参与价值，只比较已经通过全部硬门槛的结果股。
- 两者不能互相替代。个股参与价值再高，也不能打开被市场层关闭的交易许可。

### 2.2 仓位权限与配比

- 市场层先给出组合 `positionCeilingPct`。
- 条件许可只启用组合上限的 1/3，后续确认后才允许加仓；权限关闭时为 0%。
- 个股仓位按照风险调整后的参与价值在结果股之间归一化分配。
- 所有结果股的 `maximumPortfolioPct` 之和不得超过市场组合仓位上限。
- 未通过任一硬门槛的股票仓位恒为 0，不参与归一化。

## 3. 周期定义

| 因子 | 时间颗粒度 | 职责 | 权威输出 | 不允许做的事 |
| --- | --- | --- | --- | --- |
| 大周期 | 宏观/中期 | 判断市场结构与总体仓位环境 | `marketStage.bigCycle` | 被小周期、题材热度或单只股票改写 |
| 过渡节点 | 周期切换观察 | 记录修复、反弹、分歧、加强等尚未确认的切换信号 | `marketStage.transition` | 冒充或直接改写大周期 |
| 小周期 | 微观/短期 | 判断大周期内部的节奏、分歧、修复与转折 | `marketStage.smallCycle` | 覆盖大周期或单独放开交易权限 |
| 情绪阶段 | 短线参与层 | 判断核心情绪所处阶段 | `marketStage.emotionStage` | 在跨日证据缺失时伪造严格阶段 |
| 分歧强度 | 短线参与层 | 将分歧量化为小分歧、中等分歧或大分歧 | `marketStage.emotionStage.divergenceIntensity` | 用“良性/非良性”代替强度 |
| 分歧质量 | 短线参与层 | 判断分歧后的承接和修复是否有效 | `marketStage.emotionStage.divergenceQuality` | 用“大/小分歧”代替质量 |
| 承接状态 | 短线参与层 | 独立输出承接强、承接一般或承接弱 | `marketStage.emotionStage.supportState` | 仅凭一只股票的回封确认全市场承接 |
| T-1权威情绪状态 | 跨日状态层 | 为当日状态机提供精确上一交易日基准 | `marketStage.previousEmotionStage` | 读取非精确日期、盘中残片或未知状态 |
| 今日状态 | 单日观察 | 描述当日盘面表现 | `marketStage.dailyState` | 冒充大周期或小周期 |

大周期是互斥枚举，只允许：`混沌`、`主升`、`震荡`、`退潮`、`冰点`。`修复`不是大周期；冰点反弹、退潮修复、主升分歧、主升加强等均属于过渡或小周期描述。未确认的局部主升也不得提前升级为大周期主升。

页面标准展示格式：`大周期：X / 过渡节点：Y / 小周期：Z`。没有活跃过渡时可隐藏中间项；任一权威项缺失则显示“待确认”，不能拿其他周期标签补位。

### 3.1 小周期输入规则

小周期只读取 `indexSubPhase.key`、`shortTerm.key`、`dailyState.key`、`intraday.key` 等结构化枚举键。中文标签和原因说明只用于展示，不能参与关键词判定。例如“震荡结构·暂无主升细分”必须归为震荡，不能因为说明文字含“主升”而误判为加强。

“小周期加强”只允许两种等价证据路径：上游已用完整指数证据确认 `indexSubPhase.key=main_rise_strengthening`；或在缺少该细分结果时，`shortTerm.key` 已是 `main_rise/partial_main_rise`，并且 `intraday.key` 同时为 `strong_close/recovery_strong_close`。只有短线主升结构而日内强弱混合时归为震荡，日内弱收时归为分歧。赚钱效应改善和昨日涨停股的今日溢价属于后续“情绪阶段/赚钱效应”节点，不作为指数小周期加强的替代证据。

### 3.2 情绪阶段、分歧强度、质量与承接

四个维度独立输出，不能再合成“非良性分歧”这类无法判断强弱的单一标签：

- `phase`：当前属于加强、一致高热、分歧、修复、转弱或待确认等节奏阶段；
- `divergenceIntensity`：只回答分歧有多大。进入分歧阶段后，大分歧要求状态已进入 `harmful/retreat`，并同时满足负反馈锚数量、修复失败率和伤害分中的组合门槛；中等分歧由强分歧阶段、过半分歧率、至少两只修复失败或伤害分达到 25 触发；其余为小分歧；
- `divergenceQuality`：只回答分歧是否被有效承接。至少两只修复失败、承接分低于 40 且伤害分不低于 35 时为非良性；至少两只有效承接、承接分不低于 50 且修复失败数不多于承接数时为良性；其余为中性待确认；
- `supportState`：承接分不低于 58 且至少两个承接锚为承接强；承接分低于 40 或修复失败数多于有效承接数为承接弱；其余为承接一般。

这些阈值是当前规则阈值，不是已证明的最优参数。后续有效性验证必须分别统计三个维度的 T+1 表现，不能把强度和质量重新混成一个标签。

### 3.3 T-1权威情绪状态

T-1 状态只接受两类来源：同版本、精确上一交易日、完整收盘快照内已冻结的 canonical 状态；或使用相同情绪引擎对精确历史收盘快照做出的确定性回放。回放可沿交易日递归寻找已知基准，当前最大深度为 8；单日启动只允许在目标 T-1 本身是完整收盘快照且可形成非 `unknown` 状态时使用。

权威回放必须输出 `authority=canonical_exact_closing_replay`、目标交易日和回放模式。日期不精确、代次不一致、收盘证据不完整或回放结果仍为未知时，`previousEmotionStage.available=false`，跨日阶段失败关闭，不得拿旧页面标签或普通候选投票补位。

这里的 T-1 是综合情绪锚状态机的跨日基准。严格核心证据路径仍有自己更窄的 T-1 门槛；若上一交易日严格核心资格结果确实为 0 只，严格核心路径必须显示不可用，不能拿综合锚 T-1 冒充。这属于两个不同样本范围，不是同一字段再次冲突。

### 3.4 云端快照的统一决策约束

云端原始字节和 SHA 是不可改写的源证据。云端发布者必须在收盘时冻结同代 `unifiedQuantFactors v6`、`unifiedDecisionChain v3` 和按 `marketPhaseDetail.decisionContext` 重算的 `bestPicks`。桌面端只验证并原样保留这条冻结链，禁止读取本机 T-1 档案后重算，从而避免同一云端 SHA 在不同电脑上产生不同结果。

云端与本地都必须通过共享权威检查器，校验 `generationId/tradingDate/asOf`、T-1 精确日期与回放权威、步骤顺序、`unified_stock_factor_engine_v4` 个股因子权威、最多 5 只、结果股一致性和仓位合计。旧版、缺失或代次冲突的云端链直接返回 `CLOUD_FROZEN_DECISION_INVALID`，并携带源 SHA 和失败原因；不得本地补票、回退展示旧决策或放宽官方权限。

正式仓位只有一个来源：`unifiedDecisionChain.result.stocks[].positionAllocation`。旧模型的 `position`、`stopLossPlan.position`、`advice.position` 或盘前/盘后计划文字仓位不得作为执行值；它们即使与统一链股票代码相同，也只能放入明确的 `legacyObservation`。正式主选股卡、盘前直买和盘后严格计划必须按代码注入同一份 canonical allocation，并分别展示初始仓位与仓位上限。

## 4. 炒作偏好叠加

统一输出为 `speculationPreference`：

- `macro`：旧模型，判断市场以板块轮动、板块聚焦还是个股轮动等方式组织。
- `micro`：新模型，判断低位启动、高位趋势、连板情绪等具体资金表达路径。
- `combined`：只负责组合说明，不再产生第三套覆盖性结论。

使用规则：先用宏观模型确定“市场怎么组织”，再用微观模型确定“资金通过哪类股票表达”。两个结果可同时成立，也允许一项待确认；不能用其中一项替代另一项。

## 5. 个股硬门槛、结果池与参与价值

### 第一步：硬门槛

硬门槛具有否决权，不计正分。包括：

- 周期允许；
- 题材允许；
- 模式符合；
- 数据完整；
- 风险通过；
- 上游个股硬门槛通过。

任一必要条件失败，个股只保留观察或复盘，不进入参与价值排序。

### 第二步：结果股票池

硬门槛通过后形成内部决策池，再按当前周期的风险调整后参与价值排序，最多输出 5 只。内部决策池可以大于 5 只，防止前排股票被赚钱效应、题材或模式交集剔除后漏掉后续合格标的；对外正式结果始终不超过 5 只。

如果没有股票通过全部交集和硬门槛，输出 0 只，不允许用观察票、旧 `selected` 或非主路径股票补位。

正式个股三层评分只由 `quant-decision/stock-factor-engine.js` 计算。旧 `stock.score` 无论高低都不作为最终分兜底；旧 `selected/bestPicks/scenarioPlans` 也不得授予或否决风格载体。情绪 leave-one-out 只接受调用方显式传入的 `selectedCandidateCode/excludedCandidateCodes`，防止旧候选反向改写市场阶段。

### 第三步：参与价值与仓位配比

只有硬门槛通过后才计算。当前五个互斥维度为：

| 维度 | 内容 | 去重规则 |
| --- | --- | --- |
| 题材地位 | 焦点、辅助、主线题材匹配 | 同类题材命中取最大值，不相加 |
| 个股角色 | 周期角色、票型、领导力、历史核心 | 同类角色证据取最大值，不相加 |
| 结构质量 | 周期对应的涨幅/K线结构与领导力结构等级 | 正向结构在此计算，负反馈进入风险层 |
| 流动性 | 换手、量比、主力流入、双榜热度 | 每项原子事实只出现一次 |
| T+1条件溢价 | 有样本门槛的次日统计与混沌期内修复回流条件 | “修复”只表示小周期节点；回测和回流分别记录，不复用基础观察总分 |

量比只进入流动性参与价值，不再单项硬拒：`1.2–3.0` 记正常放量分，`1.0–1.2` 低分保留，`1.0`以下不给量比正分但不删除候选，`3.0`以上按过热降分。缩量票仍可依靠题材地位、主动性、结构和其他流动性证据进入排序。

领导力使用两层动态权重：大周期决定领导力在角色分中的总占比（混沌25%、主升45%、震荡35%、冰点30%、退潮0%执行权）；小周期决定内部的当日主动性/周期身份/方向带动比例。低位启动与修复为 `55/15/30`，加强为 `30/45/25`，分歧回流为 `40/30/30`，平稳运行为 `35/35/30`。分时主动性未验证时，领导力质量分上限60，且不得单独授予交易资格。

分时证据链按以下顺序取数：东财同日分钟线 → 腾讯同日分钟线 → 同交易日已持久化的真实分钟证据 → 收盘代理降级。日K熔断与分时熔断相互独立；任何分钟数据的供应商交易日与当前交易日不一致时直接丢弃。证据质量进一步分为：东财完整收盘分钟OHLC权重100%；腾讯收盘价格/成交序列因缺分钟OHLC暂按85%；未到14:55的盘中部分数据按55%且禁止取得收盘交易资格；旧来源字段不完整的历史分时最多75%；收盘代理上限60分。以上折减系数尚未校准，必须通过样本外验证后才允许调整。

执行可行性属于风险收紧层，检查价格源完整性、一字/锁价的价格发现、成交活跃度、量比拥挤、高换手、筹码偏离以及盘中触发/取消条件。明确不可买时进入硬门槛否决；证据不完整或拥挤度偏高时只标记 `conditional` 并扣风险分。该模块不预测真实成交价和滑点，也不能打开上游权限。

当正式授权关闭但市场资金路径已有观察代表时，统一链可单独输出 `observationCandidates.stocks`，上限仍为5只。观察清单分为A层“只差市场授权的重开候选”、B层“用于验证资金路径的代表”、C层“个股硬门槛已经失败的市场观察”；排序必须先按层级再按观察分。每只只展示路径、题材、领导力质量、当前缺口、重开条件与取消条件；禁止携带 `positionAllocation`、`buy` 或任何执行权。正式 `result.stocks` 与 `bestPicks` 仍保持0只。

历史v5/v6旧档只允许建立反事实回放外壳。它可以重建代次外壳、题材库与市值派生字段，但不能补造缺失的T-1情绪初始状态，也不能补造当晚决策凭证；统一标记 `provenance=counterfactual_current_engine_replay`、`asDecided=false`、`executionAuthority=false`。无法递归证明T-1的日期继续留在失败审计。

执行回放要求机器可读的时间窗口和最高高开阈值，并同时取得T+1分钟成交条。当前使用AKShare新浪不复权5分钟线，触发后按下一根5分钟K线开盘价作保守成交，再叠加5bps滑点与8bps费用压力情景；每个股票日期必须通过日线OHLC/成交额及T/T+1价格桥校验。东财交叉源不可用时只标记“新浪单源+独立日线校验”，不得写成双源确认。只有日线时只能观察近似锁价，禁止生成成交收益。排序研究中的执行回放是反事实诊断；正式as-decided验证则只读取当晚冻结凭证中的机器规则及其绑定侧车。两者均无实盘执行权。因子消融分别覆盖Top1/Top3，并对领导力、量比、执行风险和五个参与价值组件做单因子反事实排序；相关性只提示潜在重复计权。

样本外校准采用按时间前70%训练、后30%验证。成交额分界、量比阈值和分周期领导力权重必须在训练与验证中都达到至少10个真实换票/对照样本、方向一致且验证期改善，才允许形成参数建议；校准器永不自动修改生产参数。样本不足时继续保留25000亿、量比1.2和当前动态权重。

不同周期继续使用不同玩法权重与条件；统一的是分层、字段与去重方式，不是把各周期策略抹平成同一套分数。

### 风险调整

风险调整只能减分或取消，不能产生正向许可。当前包括：

- 价格透支：高位、加速、兑现、三波新高、等待回踩；
- 负反馈：不同周期下不符合参与区间的涨跌幅、套牢压力；
- 最大回撤：有足够样本时的历史最差回撤；
- 取消条件：`gamePlan.canGame === false` 等明确否决。

结果股排序与配比使用：

`finalScore = participationValue.score + riskAdjustment.score`

旧 `stock.score` 是上游观察分，不再进入最终个股排序。`canGame === true` 也不再额外加正分，因为许可本身不是收益证据。

每只最终结果股必须携带 `factorDecision` 和 `positionAllocation`，其中包含：

- `hardGate`；
- `participationValue.components`；
- `riskAdjustment.components`；
- `finalScore`；
- `deduplication` 去重声明。
- `relativeWeightPct`：结果股票之间的相对配比；
- `initialPortfolioPct`：首次条件触发时的组合仓位占比；
- `maximumPortfolioPct`：确认后仍不得超过的组合仓位占比。

## 6. 题材与个股的单向依赖

允许的依赖方向：题材原子数据和角色证据 → 题材主线 → 个股题材门槛与参与价值。

禁止的反馈环：个股总分 → 题材主线 → 同一只个股再次获得题材加分。

题材内部当前只允许使用角色授权、涨停状态、连板高度、热榜排名、成交额和涨幅排序，不读取个股最终总分。如果 provisional 焦点与题材主线不同，系统会把真实主线前置后重新计算候选，防止错误焦点留下永久剔除结果。

## 7. 权限合并规则

最终权限为各层权限的交集：

`finalAllow = generationAligned AND marketStageAllow AND indexAllow AND tradeWindowAllow AND emotionAllow AND styleAllow AND shortProfitCarrierAllow AND themeAllow AND stockModeAllow AND stockHardGateAllow`

约束：

- 任一下游门槛关闭，最终权限必须关闭；
- 观察因子不能开启权限；
- 跨代或跨交易日数据直接失败关闭；
- `selected` 仅是旧候选标记，不代表最终可交易；
- 正式股票模式门槛禁止读取旧 `selected`，只有历史有效性验证模式可以把它当共同样本池；
- 角色候选、模式候选、可执行候选必须分别统计，不得混用“候选数”。

## 8. 角色口径

- 题材角色：龙头、先锋、中军、补涨、跟随，描述题材内部地位。
- 当日角色：当日高度、主动领涨，描述当日表现。
- 周期身份：候选、确认、保留、失效，描述跨日身份。
- 执行角色：可执行、条件观察、仅复盘，是唯一能进入最终交易权限的角色层。

“当日高度”不自动等于“周期龙头”，“中军”身份也不自动获得买入资格。

## 9. 因子登记与新增规范

所有统一因子必须登记在 `FACTOR_CATALOG`，至少包含：

- `id`：稳定且唯一；
- `label`：中文业务名称；
- `layer`：所属层；
- `timeScale`：时间颗粒度；
- `owner`：唯一计算模块；
- `authority`：观察、排序、否决或最终权限；
- `output`：统一输出路径；
- `missingPolicy`：缺失时如何处理。

新增因子前必须回答：

1. 它使用哪个原子事实？
2. 这个事实是否已在同层或其他层计分？
3. 它是观察、相对排序、风险否决还是权限因子？
4. 适用于哪些周期，哪些周期禁止使用？
5. 缺数据时是未知、降级还是失败关闭？
6. 如何做历史回放、样本外验证与阈值校准？

未完成上述登记和验证的因子，只能以 `observation_only` 接入，不能参与评分或权限。

## 11. 验证不变量

每次修改必须至少验证：

- 大周期必须属于五态枚举，修复、反弹、分歧、加强、加速输入必须被拒绝或下沉；
- 大周期、过渡节点与小周期标签不同不算冲突；
- 小周期只能由结构化键判定，展示文案中的关键词不能改变结果；
- 情绪阶段、分歧强度、分歧质量和承接状态必须分别输出；
- T-1 状态必须是精确上一交易日的 canonical 收盘状态或同引擎权威回放，缺失时失败关闭；
- 宏观和微观炒作偏好同时保留；
- 下游权限不能放宽上游权限；
- 上一层关闭后，后续层不得继续生成结论；
- 跨代数据失败关闭；
- `selected`、角色候选、模式候选、可执行候选分别统计；
- 最终个股排序不读取旧 `stock.score`；
- 同类题材证据与同类角色证据采用最大值，不重复相加；
- 题材内部排序不读取个股最终总分；
- 页面统一显示大周期、活跃过渡节点和小周期，不再用一个裸“周期”字段概括三条不同时间轴。
- 正式结果最多 5 只，允许 0 只且不得补票；
- 个股仓位合计不超过市场仓位上限；
- 个股参与价值不能反向打开交易许可。
- 分时证据只能使用供应商明确交易日与分钟数据；日期错配或缺失时必须显示降级，不得用日线冒充。
- 观察候选最多5只且不携带仓位、买点或执行权，不能回填正式结果股。
- 执行可行性只能减分或否决，不得产生正向许可；真实滑点仍需盘中成交数据验证。
- 只有显式收盘、同代统一链和统一因子、合法仓位及机器触发规则全部通过时，才能生成 `live_canonical` 决策凭证。
- 正式凭证的结果成员只能来自 `unifiedDecisionChain.result.stocks`；0只必须保留为现金决策日，旧 `selected` 和观察股不能补票。
- 决策凭证必须通过 `receiptId/decisionHash/sourceHash/receiptHash` 复核；同日更晚收盘代次替换必须带 `lineage.supersedesReceiptId` 和原因。
- T+1结果只能写侧车并绑定原凭证；不得写回T日历史快照，也不得用当前引擎回放冒充当晚输出。

## 13. 决策凭证与T+1闭环

正式收盘归档在统一链和统一因子全部生成后，构造 `decisionReceipt` 并再次校验：

- `status=live_canonical` 才属于当晚真实输出；
- `status=unavailable` 只用于兼容审计，正式结果固定0只；
- `receiptId` 由交易日与决策哈希组成；
- `sourceHash` 固定同代 `generationContext/unifiedDecisionChain/unifiedQuantFactors`；
- `decisionHash` 固定市场阶段、授权、赚钱效应、题材、模式、正式结果、观察对象和因子快照；
- `receiptHash` 固定整张凭证，包括显式纠错谱系；
- 非空正式结果还必须等码取得 `bestPicks.picks[].executionReplayRule`，只能补执行证据，不能扩充成员。

T+1结果写入 `data/decision-outcomes/YYYY-MM-DD.json`，旧版本进入 `data/decision-outcome-revisions/`。侧车必须证明下一快照的供应商 `prev` 正好等于凭证T日，并校验日线价格桥和分钟条日期；状态包括 `cash_only`、`not_triggered`、`settled`、`incomplete`。验证数据始终 `executionAuthority=false`。

历史验证报告分成两部分：

1. `frozenDecisionStudy`：只读取原档内 `live_canonical` 凭证和绑定侧车，属于 `asDecided=true`；
2. `counterfactualReplayStudy`：用当前引擎重算旧收盘数据，属于 `asDecided=false`，不能解释为当晚真实决策。

现有29个旧历史档全部保留原字节并标记 `legacy_without_receipt`，不会补造凭证；真实as-decided样本从下一次通过凭证门禁的新收盘归档开始积累。

机器入口：

- `GET /api/decision-ledger/audit`：查看凭证覆盖和旧档审计；
- `GET /api/decision-ledger/current?date=YYYY-MM-DD`：读取冻结凭证及其结果侧车；
- `POST /api/decision-ledger/settle`：用本地已验证数据刷新侧车；
- `npm run audit:decision-receipts`：生成凭证审计报告；
- `npm run settle:decision-outcomes`：批量补结算；
- `A_SHARE_PYTHON=<python路径> npm run validate:minute-full`：用指定解释器执行AKShare分钟回填；依赖见 `requirements-akshare.txt`；
- `npm test`：运行归档、凭证、结算、历史真实性闭环测试。
