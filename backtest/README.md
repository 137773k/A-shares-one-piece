# 回测目录

本目录只负责冻结回测口径、读取决策凭证、模拟执行、维护组合和生成报告。

它必须把 `quant-decision/` 当作唯一策略来源，禁止复制因子、重新选股或使用观察候选补票。

## 当前阶段

`strategy-v7` 已冻结到源码提交 `da6d5e9ecfada9f253323ba4f4436e0bbfa44d5a`，契约首次加入Git的提交为 `328b11be252b276880ad2270094ccaeb3ecddb6f`，并已按append-only规则登记为当前默认契约。`strategy-v1`至`strategy-v6`继续保持字节、首次提交和登记哈希不变。

V7保留V6的决策凭证、组合、公司行动、成本和血缘会计边界，但把入场与卖出证据收紧为：

- T日收盘生成信号；
- 只读取 `decisionReceipt.decision.result.stocks`；
- T+1按冻结机器规则触发；
- 只接受完整240根、原始不复权、证券和日期匹配、内容哈希正确的1分钟K线；JQData为Tier 1，AKShare为Tier 2；旧5分钟数据只能做历史入场评价，腾讯价格序列只能观察；
- BAR_END按时间戳视为已完成，BAR_START只有到`barStart+60秒`才可观察；14:55规则只允许使用结束时刻不晚于14:55的K线；
- 触发K线自身绝不成交，使用紧接的下一根规范1分钟K线开盘价模拟入场；
- as-decided只认`live_canonical`凭证；counterfactual使用独立authority、路径、策略哈希和点时数据，禁止混入实盘凭证；
- 授权关闭且正式结果为0只的凭证保留为现金日；只有非空结果才要求授权通过；
- 买卖各5bps滑点、买卖各4bps费用压力情景；
- 使用冻结初始组合仓位；
- 仓位金额以信号日收盘完成退出、费用、公司行动和盯市后的净值为基数，旧持仓占用总仓位预算；
- 交易单位、最小买入量、递增单位、最大委托量、零股卖出和最小价位均按逐证券逐日期规则读取，不固定为100股；
- 同股持仓期间忽略新信号；待执行委托占用组合槽位并在冻结T+1窗口结束时失效；全组合最多5个不同证券；
- 待执行委托不预留现金，按触发时刻、决策排名和稳定证券身份依次处理；T收盘一次性准入，当日不动态递补、不回看分钟条；
- 每笔实际成交都会从冻结的剩余总仓位预算中扣减；未成交不扣减，后续订单不能重复使用同一份预算；
- 未触发仓位保留现金；
- T+1只能盯市；若触及实际可比成交价-7%或权威跌停价，只持久化全卖意图，不伪造T+1成交；
- 最早T+2执行卖出。卖出模块只生成intent；只有独立持仓执行器校验后的fill receipt才能改变实际仓位、释放现金或形成已实现损益；
- `sameContextIdentityRequiredFields` 约束外层position/daily/upper签名信封；内层 comparable price 凭证以 `sourceHash` 绑定成交/公司行动血缘，并作为position payload的一部分继承外层 `sourceDecisionHash` 与 canonical payload hash。引擎另外强制内外层证券、交易所、交易日和generation一致，不要求重复存一份无新增约束的inner `sourceDecisionHash`；
- -7%止损以实际可比成交价为基准；浮盈保护保留最高浮盈70%，历史最高价证据必须覆盖到上一交易日收盘，当根K线最高价不能倒灌保护线；
- 涨停回落按昨收计算3个百分点，触发分钟不计，之后必须再有5根完整1分钟未回封；回封会重置确认；
- 买一封单降至初始封单30%并连续30秒时，FULL层只生成一次“卖当前实际仓位50%”意图；一分钟成交量绝不代理封单量；
- CORE_1M与FULL_1M_TICK分别报告且禁止合并。当前生产入口不接受调用方手工Tick，所以FULL在真实签名Tick接入前不可作为生产完整策略；
- 负反馈且个股MA5正乖离严格大于10%、14:55累计成交量严格超过前两完整交易日最大值且前日涨幅领先当日不少于7个百分点，均生成全卖意图；
- 14:55仍有浮盈、权威趋势身份有效、站在个股MA5和70%浮盈保护线以上时可以继续持有，不设固定最大持有天数；条件失效即退出；
- 停牌使用最后一个已验证收盘价盯市并标记估值陈旧；不同板块、ST及日期对应的涨跌停价必须来自逐证券权威数据，禁止固定百分比推断；
- 收盘等于或低于权威跌停价一律不成交；卖出滑点后跌破跌停价同样不成交，不使用成交量推断排队成功；
- 公司行动按不可变证券身份连续处理；分红、送转、零股和终止对价缺少权威证据时整次运行标为不完整，禁止宣称绩效；
- 分红、送转和配股权益只按供应商股权登记日收盘持股数量计算；除权日新买入不会倒推获得已过登记日的权益；
- 日线、分钟线、涨跌停价、成交价和盯市价全部使用原始不复权价格，公司行动只通过V1账本处理，禁止与前后复权价格重复调整；
- 超过逐证券最大委托量或5%成交量参与率时整笔不成交，不拆单、不缩量；
- 数据集结束仍未卖出时只报告未实现损益，不合成卖出；
- as-decided与counterfactual结果永不合并。

V7沿用V6冻结的总收益、最大回撤、胜率、Profit Factor、换手率、暴露率、持有期和计划/实际仓位偏差公式及零分母返回值，并增加`sellVariant`分组。公司行动、后继证券、分红和终止对价仍沿原始持仓血缘合并，只计一次胜负；未完全结算的血缘把已收现金、应收款、后继证券市值、原始成本和全部费用统一计入期末未实现损益。

当前仍缺少经验证的数据集清单、决策凭证锚、回测引擎锚、独立V7持仓执行器和成交回执锚。因此`formalPerformanceEligible=false`，项目处于“契约自身可校验、正式绩效不可执行”状态。仅创建同名文件不构成验证；各manifest的schema、字节哈希、代次、证券、交易日和决策哈希校验未实现前继续失败关闭。

现有`quant-decision/decision-outcome.js`及其侧车只可用于T+1评价验证，不能作为已实现卖出收益或正式资金曲线输入。正式运行入口会失败关闭，直到上述五类锚点全部完成并通过验证。

## 命令

```powershell
npm run backtest:contract:verify
npm run backtest:preflight
npm run test:backtest-contract
```

`backtest:contract:verify`校验冻结契约、源码提交和registry；`backtest:preflight`校验能否正式执行。当前后者应以退出码2失败，并明确列出缺少的数据集、决策凭证、引擎、持仓执行器和成交回执锚，这属于预期门禁，不是测试异常。

策略源码、参数或因子登记表发生变化后，现有契约应立即校验失败；必须创建新契约版本，禁止覆盖旧版本。

`contracts/registry.json`把每个契约哈希锚定到其契约文件首次进入Git的提交。修改已登记版本后即使同时重算文件内哈希和注册表，仍会因首次提交不一致而失败；规则变化只能新增版本。
